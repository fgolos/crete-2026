# Crete 2026 Coding Instructions

## Commit Policy
- **NEVER commit changes automatically**
- Always wait for explicit user confirmation before running `git commit`
- If changes are staged and work is complete, ask: "Ready to commit? Please confirm."
- Only commit when user explicitly says "commit", "commit this", "commit now", "push", etc.

## Code Style & Workflow
- Use `multi_replace_string_in_file` for batch edits (more efficient than sequential replacements)
- Prefer test-driven verification for UI/interactive changes
- Always check for errors with `get_errors` after making file edits
- Open browser to test before committing UI changes

## Session Management
- Keep `/memories/session/` updated for multi-step tasks and brainstorming
- Document decisions and implementation details in session memory
- Update repository memory (`/memories/repo/`) for verified project patterns

## Testing & Validation
- For interactive features: open browser, test functionality, take screenshots
- For code changes: verify with `get_errors` and run tests if available
- Document test results in commit messages or session notes

## File Operations
- Always include 3-5 lines of context when using `replace_string_in_file`
- Avoid creating temporary documentation files unless explicitly requested
- Use workspace-relative paths in file links
